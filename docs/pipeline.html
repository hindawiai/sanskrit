Historical Hindawi pipeline

  1. Native-language source: program written with localized keywords/identifiers in a supported script.
  2. Romenagri / script conversion: normalize to compiler-acceptable transliteration/ACII representation; legacy filters also bridge Unicode, ISCII and APCISR paths.
  3. Localized front-end translation: language-specific filters/translators map the localized language's vocabulary and syntax to the corresponding established toolchain language.
  4. Existing toolchain: C/C++ use GCC-compatible compilation; Shabda/Vyaakaran are lexer/parser-generator counterparts; assembly, BASIC/LOGO, and JVM-oriented Kritrim have their own back ends.
  5. Artifact: native executable or JVM-targeted artifact, depending on the language pipeline.

Historical sources describe this as a reuse strategy: localized source is translated into compiler-acceptable form, then an existing compiler produces machine code. The precise command sequence must be documented per language from its actual scripts, not assumed identical across the suite.

Current Pushkalāvatī pipeline

  1. Source index: 3,983 sūtra records in data/sutras.json.
  2. Classification and meta-grammar: evidence-bounded functional categories; classification is not executable semantics.
  3. Rule IR: operations and contexts recorded separately from generic handlers.
  4. Canonical sound tokens: current JS adapter segments IAST-like strings; table-key audit reports coverage but does not yet emulate complete Romenagri byte encoding.
  5. Execution: tested forward operations plus inverse-reduction candidate generation; ambiguity and unresolved states are preserved.
  6. Validation: source-linked positive vectors, negative applicability checks, corpus counts, and JS/Python parity where implemented.

Browser execution

GitHub Pages can execute static JavaScript but cannot invoke native GCC, arbitrary shell pipelines, or sed directly. The browser laboratory therefore runs the supported Sūtram subset and selected rule/token demonstrations. Native C utilities and original sed filters require a server/build step or a verified WebAssembly build.

Do not describe a static page as compiling every historical language until each frontend, runtime and backend is built and validated in-browser or through a remote service.
