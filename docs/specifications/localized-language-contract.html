CROSS-LANGUAGE CONTRACT

Localized language implementation contract

Specification index

Every language package must specify

  1. Canonical language name, historical alias, version, target language/toolchain, supported scripts, and source provenance.
  2. Lexical specification: keyword table, identifiers, numbers, string/comment syntax, longest-match rules, Unicode normalization and invalid-character policy.
  3. Grammar and semantics, with a versioned feature matrix.
  4. Translation mapping from localized source to canonical intermediate/source form; mappings must be data-driven where possible.
  5. Exact compilation stages, command lines, dependencies, environment variables, outputs, and error propagation.
  6. Runtime/ABI and target-specific assumptions.
  7. Positive and negative golden fixtures; round-trip and metamorphic tests; reproducible build metadata.
  8. License, attribution, security model, and generated-output provenance.

Compilation contract

source text
  → decode / normalize
  → localized lexical conversion
  → parse or source-to-source translation
  → canonical target source / IR
  → established compiler, parser generator, assembler, or JVM tool
  → artifact + diagnostics + source map/provenance

Stages vary by language. This is a shared interface contract, not a claim that every historical Hindawi language uses every stage.

Regression policy

Every bug fix adds a fixture that fails before the fix. Golden outputs must be byte-exact when the format is deterministic. Tests must distinguish unsupported input from invalid input and from a valid input to which a rule does not apply.
