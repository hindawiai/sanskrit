1 · Sūtram browser runner

2 · Sanskrit sound-token audit

Tokenization is a rule-engine representation, not a claim that the legacy ACII bytes are phoneme IDs. Unsupported mappings are reported, never guessed.

Enter a sound string and audit it.

3 · Rule-operation demonstrator

Run a small, explicit set of vowel sandhi examples using the current rule-operation definitions.

Example: upa + indra → upendra (6.1.87).

4 · Compiler and Sanchalan frontend

Use the Sūtram C/Rust compiler to generate native source and raise the documented C/Rust subset. Use the Sanchalan Suktam frontend to inspect lexical IR and generate C/Rust reporting programs.

Track status in the task and feature inventory and test register.

Execution boundaries

  • Available in this page: Sūtram subset runner, Sanskrit sound-tokenization/table-key audit, selected rule-operation demonstrations.
  • Requires a native toolchain or a future verified WebAssembly build: the original Romenagri C utilities, GCC-backed HPS compilers, sed filters, and native code generation.
  • The complete Romenagri upstream source and original Perso-Arabic filter must be vendored and parity-tested before claiming that the browser reproduces them.
