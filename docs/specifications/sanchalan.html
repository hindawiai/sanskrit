Sanchalan Suktam

Specification status: lexical front end and reporting backend. Full grammar and OS semantics remain open.

Source and status

Source: Abhishek Choudhary, Sanchalan Suktam V1.0 (2026), AyeAI, DOI 10.5281/zenodo.23277242. The supplied source explicitly states it is not guaranteed to be the final executable version.

Lexical/parser contract

  1. Read verse bodies ending in ॥N॥, accepting Devanagari and ASCII digits.
  2. Normalize to Unicode NFC.
  3. At each code-point offset, choose the longest known technical lexeme.
  4. Record token ID, role, proposed operation, and source span.
  5. Preserve unmatched spans exactly as residual material.
  6. Report duplicate/gapped verse numbering; do not repair it silently.

Machine-readable grammar: grammar.json. The executable front end exposes the same rule IDs as SUK-001 through SUK-006.

IR and code generation

Each verse contains recognized nodes, operation-code proposals, residual spans, and a lexical status. Generated C/Rust programs report this IR. They do not call OS APIs or execute process, memory, pipe, terminal, or signal operations.

Current measured output from the checked-in source: 22 verses, 134 lexical nodes, 828 residual code points. These are inventory metrics, not grammatical-accuracy measures.

Open semantic tasks

  • Review the semantic meaning of each verse against the intended OS/runtime contract.
  • Resolve padaccheda and sandhi with source-verified rules; preserve ambiguity.
  • Define typed IR operations, preconditions, failure modes, resource ownership and platform behavior.
  • Implement and test runtime backends only after the semantic contract is accepted.
  • Compile generated Rust in CI when rustc is available.
